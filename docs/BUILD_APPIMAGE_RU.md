# Сборка AppImage

[English version](BUILD_APPIMAGE.md).

`cmd/appimage-build` собирает Linux-версию клиента и упаковывает её вместе
с квадратной иконкой 256×256, `.DirIcon`, desktop-файлом, лаунчером и
лицензионными уведомлениями. Нужны Go, C-компилятор и библиотеки разработки
для обычной Linux-сборки, а также
[appimagetool](https://github.com/AppImage/appimagetool).
Новые модули Go не требуются.

## appimagetool

Команда использует `-appimagetool` или `APPIMAGETOOL`, если они заданы,
затем ищет `appimagetool` в `PATH`. Иначе она скачивает официальный
[continuous-выпуск](https://github.com/AppImage/appimagetool/releases/tag/continuous)
для архитектуры **машины сборки** (x86_64 или aarch64). Готовый исполняемый
файл сохраняется в `$XDG_CACHE_HOME/komarugram-go/appimage-build` (обычно
`~/.cache/komarugram-go/appimage-build`). Следующие сборки используют его
без проверки обновлений. Чтобы скачать новый выпуск, удалите файл из кеша.
Неудачное или прерванное скачивание не заменяет кешированный инструмент.

Для конкретной версии инструмента или работы без сети укажите локальный
файл: `-appimagetool ~/tools/appimagetool.AppImage`. Ошибочный явно заданный
путь приводит к сообщению об ошибке, а не к скачиванию.

Упаковщик запускается с `APPIMAGE_EXTRACT_AND_RUN=1`, поэтому для сборки
не нужен FUSE. Сам `appimagetool` обычно скачивает runtime AppImage;
флаг `-runtime /absolute/path/to/runtime` позволяет использовать локальный файл.
Для повторяемой сборки без сети сохраните проверенные версии обоих файлов.

## Сборка

Из корня репозитория:

```sh
go run ./cmd/appimage-build -o /tmp/KomaruGram.AppImage
```

При нехватке памяти:

```sh
GOMAXPROCS=1 GOGC=50 GOMEMLIMIT=1792MiB go run ./cmd/appimage-build -low-memory -o /tmp/KomaruGram.AppImage
```

Команда собирает по одному пакету и по умолчанию использует `GOGC=50`.
Режим `-low-memory` также задаёт `GOMAXPROCS=1` и `GOMEMLIMIT=1792MiB`, если
они не установлены в окружении, и отключает инлайнинг только в
`github.com/gotd/td/tg`. Это может снизить производительность готового
приложения; лимит памяти мягкий. Подробнее —
[в инструкции по сборке при нехватке памяти](BUILD_LOW_MEMORY_RU.md).
Сжатие SquashFS также выполняется одним потоком.

`-tags nowayland` или `-tags novulkan` передаёт теги сборки Go.
Флаг `-keep-work` сохраняет временный AppDir и выводит его путь; иначе он
удаляется, в том числе при ошибке. Неудачная сборка или упаковка не
заменяет уже существующий выходной AppImage. Без `-o` результат сохраняется
как `KomaruGram-x86_64.AppImage` или `KomaruGram-aarch64.AppImage` в системном
временном каталоге. Все параметры доступны через `-h`.

## Запуск и ограничения

```sh
/tmp/KomaruGram.AppImage -demo
```

Лаунчер сохраняет аргументы и рабочий каталог вызывающей стороны.
При обычном запуске используются привычные настройки и аккаунты.
`-demo` работает на вымышленных данных и не обращается к аккаунту Telegram.
Встроенный установщик уже распознаёт `APPIMAGE` и не предлагает самоустановку.

Это небольшой AppImage, использующий системные графические библиотеки и
libc. EGL, X11, Wayland, драйверы, FFmpeg и браузеры в него не упаковываются.
Собирайте на самом старом дистрибутиве glibc, который планируете поддерживать,
и проверяйте на остальных. Упаковка glibc-бинарника из Mint не делает его
совместимым с Alpine/musl. Эта команда не обеспечивает такую совместимость
или полностью автономный дистрибутив приложения.

Иконка находится внутри файла. Для её отображения файловым менеджером нужен
thumbnailer с поддержкой AppImage; добавление в меню приложений требует
регистрации desktop-файла внешним инструментом интеграции. См.
[спецификацию AppDir](https://docs.appimage.org/reference/appdir.html).

Проверено на Linux Mint 22.3, x86_64, XFCE/X11 в VirtualBox с appimagetool
build 313 (`854e19e`) и type2-runtime `8f39b89`.
ARM64 и другие рабочие столы вживую не проверены.
