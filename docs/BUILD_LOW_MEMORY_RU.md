# Сборка при ограниченном количестве памяти

[English version](BUILD_LOW_MEMORY.md).

Для первой сборки стоит предусмотреть около 4.5 ГБ оперативной памяти: основная часть нужна сгенерированному пакету `github.com/gotd/td/tg`. Это ориентир: пик зависит от версии Go, целевой платформы и параллелизма. Закройте ненужные приложения. Последующие сборки используют кеш Go и обычно проходят значительно быстрее.

На Linux/macOS (POSIX shell) собирайте по одному пакету, ограничьте параллелизм компилятора и запускайте сборку мусора чаще:

```sh
GOMAXPROCS=1 GOGC=50 GOMEMLIMIT=2GiB go build -p 1 -ldflags="-s -w" -buildvcs=false -o komarugram ./cmd/messenger
```

На Windows (PowerShell) те же настройки работают и с `gogio`; `GOFLAGS` передаёт `-p=1` его командам Go:

```powershell
$env:GOMAXPROCS = "1"
$env:GOGC = "50"
$env:GOMEMLIMIT = "2GiB"
$env:GOFLAGS = "-p=1"
gogio -ldflags="-s -w" -icon=./assets/logo_round.png -target=windows -o komarugram.exe ./cmd/messenger
```

`-p 1` ограничивает число одновременно выполняемых команд сборки; `GOMAXPROCS=1` также уменьшает параллелизм внутри каждого процесса Go. `GOGC=50` снижает расход памяти за счёт более частой сборки мусора. `GOMEMLIMIT=2GiB` — пример мягкого лимита для каждого процесса Go, а не ограничение всей сборки или её RSS: оставьте память для ОС, нативных инструментов и других приложений. Живые данные пакета могут превышать лимит; дальнейшее снижение способно сильно замедлить компиляцию, не предотвратив out of memory. Эти настройки снижают расход памяти ценой скорости сборки; swap может помочь с оставшимися пиками.

Если `gotd/td/tg` всё равно не помещается, добавьте `-gcflags=github.com/gotd/td/tg=-l` к `go build` (или в `GOFLAGS` при использовании `gogio`). Это отключает инлайнинг только в этой зависимости и может снизить производительность готового приложения. Кросс-сборки Windows с этим флагом прошли в Linux VM с лимитом памяти 2.25 GiB; см. [подробности проверки](RICH_TEXT.md#focused-validation) (на английском).

На Haiku `haiku-build` поддерживает тот же режим `-low-memory` (в том числе с `-test`): он использует `-p 1`, задаёт значения по умолчанию `GOGC=50`, `GOMAXPROCS=1`, `GOMEMLIMIT=1792MiB` и отключает инлайнинг только в gotd. Явно заданные ограничения в окружении сохраняются:

```sh
go run ./cmd/haiku-build -low-memory -o ~/apps/KomaruGram
```
